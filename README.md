# نظام الكاشير (POS System)

نظام كاشير احترافي مبني بـ Electron + Vite + Supabase، واجهة عربية بالكامل مع دعم RTL.

## المكونات
- تسجيل دخول عبر Supabase Auth
- **دعم الفروع المتعددة (Multi-Branch)**: كل فرع له مخزونه ومبيعاته وعملاؤه ومصاريفه وتقاريره ومستخدموه بشكل مستقل
- إدارة المنتجات (إضافة / تعديل / حذف / بحث / باركود)
- إدارة الأقسام
- شاشة كاشير (سلة، بحث، مسح باركود)
- إتمام البيع + إنشاء فاتورة
- طباعة فواتير حرارية (80mm) عبر Electron
- سجل المبيعات + استرجاع + إعادة طباعة
- تقارير يومية وشهرية + الأكثر مبيعاً
- تتبع المخزون + سجل الحركات + تسوية الجرد + **نقل مخزون بين الفروع**
- العملاء + لوحة المبيعات + الحسابات (إيرادات/مصروفات يدوية فقط — بدون فواتير أو مدفوعات موردين)
- الموردون + فواتير المشتريات (زيادة المخزون تلقائيًا) + كشف حساب المورد ورصيده
- **المالية**: لوحة أرقام بسيطة محسوبة تلقائيًا (إجمالي المبيعات، إجمالي المصروفات، صافي الربح لفترة زمنية، وقيمة المخزون وقيمة المواد الخام ورصيد الموردين المستحق لحظيًا) + عرض مبسّط لكل مورد (إجمالي الفواتير، إجمالي المدفوع، المتبقي)
- المستخدمون والصلاحيات (مدير/مشرف/كاشير) + تخصيص كل مستخدم لفرع
- إعدادات المتجر والطابعة

## 1) إعداد قاعدة البيانات (مرة واحدة)
1. افتح مشروع Supabase الخاص بك.
2. اذهب إلى **SQL Editor** ثم **New query**.
3. شغّل الملفات **بالترتيب التالي** (كل ملف في query منفصل، انسخ المحتوى كاملاً واضغط Run):
   - `sql/schema.sql`
   - `sql/migration_v2.sql`
   - `sql/migration_v3.sql`
   - `sql/migration_v4.sql` ← **يضيف دعم الفروع المتعددة**
   - `sql/migration_v5.sql` ← **يضيف/يؤمّن جداول الموظفين + دعم المزامنة الأوفلاين**
   - `sql/migration_v6.sql` ← يجعل الأقسام مرتبطة بكل فرع على حدة
   - `sql/migration_v7.sql` ← يضيف تتبع آخر تسجيل دخول
   - `sql/migration_v8.sql` ← **يضيف الموردين والمشتريات**
   - `sql/migration_v9.sql` ← يضيف خيار "مادة خام" للمنتجات (تستخدمه لوحة المالية)
   - `sql/migration_v10_client_trials.sql`
   - `sql/migration_v11_cash_drawer.sql`
   - `sql/migration_v12_customer_credit.sql`
   - `sql/migration_v13_branch_settings.sql` ← **ينقل إعدادات الفرع (الشعار، الضريبة، الطابعة) إلى جدول الفروع نفسه**، بحيث تكون كل الإعدادات (اسم/عنوان/هاتف الفرع، الشعار، الطابعة، نسبة الضريبة) خاصة بكل فرع تمامًا ولا تتأثر بها الفروع الأخرى
   - ثم شغّل الملفات المتبقية بالترتيب: `migration_v14_thermal_printing.sql` حتى `migration_v22_supplier_ledger_reconciliation.sql`.
     هذه الخطوة ضرورية خصوصًا لقاعدة بيانات قديمة؛ فهي تضيف حقول المستخدمين وربط تسجيل الدخول والمزامنة وسياسات عزل الفروع.
4. أنشئ أول مستخدم (مدير):
   - Authentication → Users → Add user (بريد إلكتروني + كلمة مرور).
   - في SQL Editor نفّذ:
     ```sql
     update public.profiles set role = 'admin', full_name = 'المدير'
     where id = '<UUID الخاص بالمستخدم>';
     ```
   ملاحظة: المدير (`role = 'admin'`) بدون فرع مخصص (`branch_id = null`) يملك تلقائيًا صلاحية الوصول لكل الفروع.
   المشرف والكاشير يجب تخصيص فرع لهم من صفحة "المستخدمون" داخل التطبيق قبل تسجيل الدخول، وإلا سيُرفض الدخول.
5. أضف فروعك الإضافية (غير الفرع الافتراضي "الفرع الرئيسي") من صفحة "الفروع" داخل التطبيق (متاحة للمدير فقط).

اتصال Supabase موجود مسبقاً في `src/lib/supabase.js` (URL + Publishable Key).

## 2) التشغيل أثناء التطوير
```bash
npm install
npm run electron:dev
```
هذا يشغّل خادم Vite + نافذة Electron معاً.

## 3) البناء للإنتاج
```bash
npm run build      # يبني واجهة الويب في dist/
npm run dist        # يبني تطبيق سطح مكتب قابل للتوزيع (عبر electron-builder)
```

## 4) الطابعة الحرارية
- في تطبيق سطح المكتب: اذهب إلى **الإعدادات** واختر الطابعة الحرارية المتصلة
  بجهازك من القائمة، ثم اضغط "حفظ".
- استخدم "طباعة تجريبية" للتأكد من عمل الطابعة.
- الطباعة تعمل فقط داخل تطبيق Electron (وليس أثناء المعاينة في المتصفح فقط،
  حيث تفتح نافذة طباعة عادية كبديل).

## هيكل المشروع
```
electron/        عمليات Electron الرئيسية (النافذة + الطباعة)
src/
  lib/            supabase.js, auth.js, printer.js, settings.js, toast.js
  lib/db/         استعلامات CRUD لكل جدول
  i18n/           قاموس الترجمة العربية (قابل للتوسعة للغات أخرى)
  components/     عناصر واجهة مشتركة (app shell)
  pages/          الشاشات: تسجيل الدخول، الكاشير، المنتجات، الأقسام...
  styles/         متغيرات التصميم + مكونات + تخطيط عام
sql/schema.sql    مخطط قاعدة البيانات الكامل لتشغيله على Supabase
```

## دعم لغات إضافية مستقبلاً
كل النصوص تمر عبر `t('key')` من `src/i18n/index.js`. لإضافة لغة جديدة:
1. أنشئ ملف قاموس جديد (مثل `src/i18n/en.js`) بنفس المفاتيح.
2. أضفه إلى `dictionaries` في `src/i18n/index.js` وحدد اتجاهه (rtl/ltr).

## الفروع المتعددة (Multi-Branch)
- **المدير**: بدون فرع مخصص (`branch_id = null`) → يرى قائمة اختيار فرع أعلى الصفحة
  ("كل الفروع" أو فرع محدد). يمكنه إدارة كل الفروع، مقارنة أدائها، ونقل المخزون بينها.
- **المشرف / الكاشير**: مقيّدون بفرعهم المخصص فقط (`branch_id`)، بدون قائمة اختيار.
- المنتجات، المبيعات، العملاء، الحسابات، المخزون كلها معزولة لكل فرع تلقائيًا.
- الأقسام (categories) فقط مشتركة بين كل الفروع (تصنيف عام).
- نقل المخزون بين الفروع متاح فقط للمدير، من صفحة "المخزون" → تبويب "نقل بين الفروع"،
  ويُحفظ سجل كامل لكل عملية نقل.

## Offline-First (SQLite محلي + مزامنة تلقائية)
التطبيق يقرأ ويكتب دائمًا من قاعدة بيانات SQLite محلية أولاً (سريعة، تعمل بدون
إنترنت بالكامل)، وفي الخلفية يزامن أي تغييرات مع Supabase تلقائيًا كل ما توفر
اتصال. شارة صغيرة أعلى كل صفحة توضح الحالة:
🟢 متصل · 🟡 جارٍ المزامنة · 🔴 غير متصل (والتطبيق يستمر يشتغل عادي).
التفاصيل الكاملة والقرارات التصميمية (خصوصًا كيفية تفادي ازدواج خصم المخزون
عند البيع أوفلاين) موثقة في **`OFFLINE_FIRST.md`**.
